---
title: "Tools"
description: "Every tool the NeetoAuth MCP server exposes, grouped by resource."
---

You do not need these names to use the server. Ask in plain language and the assistant picks the right tool. The list is here for when you want to know exactly what a connection can do. Most tools match a [REST API](/api/introduction) endpoint and link to its reference. The server exposes five tools across three resources.

Every tool takes an optional `workspace` argument, the subdomain of a connected workspace. Left out, it runs against the workspace the connection was set up with. `ListWorkspaces` reports the values you can pass.

What a tool returns depends on the credential. Over [OAuth](/mcp/authentication#oauth-scoped-to-you), lists come back filtered to the permissions of the person who approved the connection, and a record they cannot open is refused rather than returned; an [API key](/mcp/authentication#api-key-scoped-to-the-workspace) reaches the whole workspace. A tool that creates, updates, or deletes is also refused when the connection was not granted the **Create and update** or **Delete** permission. `CreateUser` needs **Create and update**, and `DeactivateUser` needs **Delete**.

## Workspaces

| Tool | What it does |
| --- | --- |
| `ListWorkspaces` | Lists the workspaces this connection can access. Pass a returned subdomain as the `workspace` argument of other tools to target that workspace. |

`ListWorkspaces` has no REST endpoint, which is why it is not linked.

### ListWorkspaces

| Argument | Required | Description |
| --- | --- | --- |
| `page` | | Page number (default: 1) |
| `page_size` | | Workspaces per page (default: 15, max: 100) |

Returns `workspaces`, each with `name`, `subdomain` and `default` (whether it is the workspace tools run against when none is named), alongside `total_count`, `page`, `total_pages` and `page_size`. Ordered by name.

## Users

| Tool | What it does |
| --- | --- |
| [`ListUsers`](/api/users/list) | Lists active members with their email, organization role, and name. Optionally filters by an email substring, matched case-insensitively. |
| [`CreateUser`](/api/users/add) | Invites a new member and emails them an invitation, optionally granting roles in specific neeto products at the same time. |
| [`DeactivateUser`](/api/users/remove) | Deactivates an active member by exact email address and destroys their sessions across every neeto product. |

### ListUsers

| Argument | Required | Description |
| --- | --- | --- |
| `email` | | Filter by email substring (case-insensitive, partial match) |
| `page` | | Page number (default: 1) |
| `page_size` | | Users per page (default: 15, max: 100) |

Returns `users`, each with `email`, `role`, `first_name` and `last_name`, alongside `total_count`, `page`, `total_pages` and `page_size`. Deactivated members are never returned.

### CreateUser

| Argument | Required | Description |
| --- | --- | --- |
| `email` | Yes | Email of the user to invite |
| `role` | Yes | Organization role: `owner` or `non_owner` (case-insensitive) |
| `first_name` | | Defaults to `-` if omitted |
| `last_name` | | Defaults to `-` if omitted |
| `apps` | | Product grants, each a `name` and a `role` available in that product |

Returns the invited user together with the `apps` grants the server resolved. Run `ListProducts` first so the `name` and `role` values match what the workspace offers.

### DeactivateUser

| Argument | Required | Description |
| --- | --- | --- |
| `email` | Yes | Exact email address of the active user to deactivate |

Returns `deactivated` and the `email`. It fails if the user does not exist, is already deactivated, or if deactivating would leave the workspace without an owner. The action is recorded in the workspace audit log, and is reversible only through the NeetoAuth admin UI.

## Products

| Tool | What it does |
| --- | --- |
| [`ListProducts`](/api/products/list) | Lists the neeto products enabled for the workspace, each with the role names available in it. |

### ListProducts

| Argument | Required | Description |
| --- | --- | --- |
| `page` | | Page number (default: 1) |
| `page_size` | | Products per page (default: 15, max: 100) |

Returns `products`, each with a `name` and its `roles`, alongside `total_count`, `page`, `total_pages` and `page_size`. Use the pairs to build the `apps` argument for `CreateUser`.
