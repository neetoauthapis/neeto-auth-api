## Sign in with your NeetoAuth account

<Tabs>
  <Tab title="Claude">
    1. Open **[Customize > Connectors](https://claude.ai/customize/connectors)**, click **Add**, then click **Add custom connector**.

       <Frame caption="Add custom connector is the only item under the Add button.">
         <img src="/assets/mcp/claude-add-menu.png" alt="Menu under the Add button in Claude's Connectors settings, with the single item Add custom connector" />
       </Frame>

    2. Enter the name NeetoAuth and paste the server URL.

       ```
       https://connect.neetoauth.com/mcp/messages
       ```

       <Frame caption="The Add custom connector dialog, ready to submit.">
         <img src="/assets/mcp/claude-add-custom-connector-dialog.png" alt="Claude's Add custom connector dialog with the name NeetoAuth and the server URL https://connect.neetoauth.com/mcp/messages filled in, and a Continue button" />
       </Frame>

    3. Click **Continue** and sign in to NeetoAuth. See [What the sign-in looks like](#what-the-sign-in-looks-like).

    NeetoAuth then works in claude.ai, the Claude desktop app, Claude mobile, and Cowork.

    On a Team plan, an Owner must first add the same server URL under **[Organization settings > Connectors](https://claude.ai/admin-settings/connectors)**. Then connect it from your own Connectors list.

    To disconnect, open **[Customize > Connectors](https://claude.ai/customize/connectors)** and remove NeetoAuth.
  </Tab>

  <Tab title="ChatGPT">
    1. Go to [chatgpt.com](https://chatgpt.com) and open **Settings → Security and login**.
    2. Turn on **Developer mode**.

       <Frame>
         <img src="/assets/mcp/chatgpt-developer-mode.png" alt="ChatGPT's Developer mode setting, tagged Elevated risk, with its toggle switched on" />
       </Frame>

       If you do not see **Developer mode**, your ChatGPT workspace admin has turned it off. Ask them to allow it.

    3. Go to [chatgpt.com/plugins](https://chatgpt.com/plugins) and click the **plus** button.
    4. In **New Plugin**, enter the name NeetoAuth, set **Connection** to **Server URL**, and paste:

       ```
       https://connect.neetoauth.com/mcp/messages
       ```

    5. Leave **Authentication** on **OAuth**.
    6. Tick **I understand and want to continue**, then click **Create**.
    7. Sign in to NeetoAuth. See [What the sign-in looks like](#what-the-sign-in-looks-like).
  </Tab>

  <Tab title="Claude Code">
    1. Add the server:

       ```bash
       claude mcp add --transport http neetoauth https://connect.neetoauth.com/mcp/messages
       ```

    2. Start Claude Code and run `/mcp`.
    3. Pick **neetoauth** and sign in to NeetoAuth in the browser.
  </Tab>

  <Tab title="Cursor">
    1. Add the server to `~/.cursor/mcp.json`:

       ```json
       {
         "mcpServers": {
           "neetoauth": {
             "url": "https://connect.neetoauth.com/mcp/messages"
           }
         }
       }
       ```

    2. Restart Cursor.
    3. Sign in to NeetoAuth when Cursor asks.
  </Tab>

  <Tab title="Gemini CLI">
    1. Add the server to `~/.gemini/settings.json`. Use `httpUrl`, not `url`:

       ```json
       {
         "mcpServers": {
           "neetoauth": {
             "httpUrl": "https://connect.neetoauth.com/mcp/messages"
           }
         }
       }
       ```

    2. Start Gemini CLI and sign in to NeetoAuth when it asks.
  </Tab>

  <Tab title="Codex">
    1. Add the server to `~/.codex/config.toml`:

       ```toml
       [mcp_servers.neetoauth]
       url = "https://connect.neetoauth.com/mcp/messages"
       ```

    2. Run this command and sign in to NeetoAuth in the browser:

       ```bash
       codex mcp login neetoauth
       ```
  </Tab>

  <Tab title="VS Code">
    You need VS Code 1.99 or later, with GitHub Copilot in **Agent** mode.

    1. Create `.vscode/mcp.json` in your workspace. Use `servers`, not `mcpServers`:

       ```json
       {
         "servers": {
           "neetoauth": {
             "type": "http",
             "url": "https://connect.neetoauth.com/mcp/messages"
           }
         }
       }
       ```

    2. Sign in to NeetoAuth when VS Code asks.
  </Tab>

  <Tab title="Windsurf">
    1. Add the server to `~/.codeium/windsurf/mcp_config.json`. Use `serverUrl`, not `url`:

       ```json
       {
         "mcpServers": {
           "neetoauth": {
             "serverUrl": "https://connect.neetoauth.com/mcp/messages"
           }
         }
       }
       ```

    2. Turn on the server under **Settings → Cascade → MCP Servers**.
    3. Sign in to NeetoAuth when Windsurf asks.
  </Tab>
</Tabs>

### What the sign-in looks like

<Steps>
  <Step title="Connect your workspace">
    Enter your workspace subdomain, or paste the workspace URL. For `acme.neetoauth.com`, enter `acme`. The **Find your workspace subdomain** link on this screen opens the [Workspace subdomain](/mcp/workspace-subdomain) page.

    <Frame caption="The first screen of the NeetoAuth sign-in.">
      <img src="/assets/mcp/oauth-connect-workspace.png" alt="NeetoAuth dialog headed 'Connect your workspace' with a field for the workspace subdomain, a .neetoauth.com suffix, and a Continue button" />
    </Frame>
  </Step>
  <Step title="Sign in">
    Sign in to that workspace, if you are not signed in already.
  </Step>
  <Step title="Choose what the assistant can do">
    **Read** and **Stay connected** are always on. Tick **Create and update** and **Delete** only if the assistant needs them.

    The workspace you entered is always connected. If your email belongs to other workspaces, tick any you also want under **Additional workspaces to connect**. The permissions you approve apply to every connected workspace.

    <Frame caption="Choosing the permissions and any additional workspaces.">
      <img src="/assets/mcp/oauth-authorize.png" alt="NeetoAuth 'Authorize access' screen showing the workspace and signed-in email, a 'What this connection can do' list with Read and Stay connected always granted and Create and update and Delete as tickable boxes, a 'Workspaces to connect' list with three workspaces, and Cancel and Authorize buttons" />
    </Frame>
  </Step>
  <Step title="Authorize">
    Click **Authorize**.
  </Step>
</Steps>

To add a workspace or a permission later, sign in again and tick it.

## Use an API key

An API key reaches the whole workspace, not only what you can see. Use it for automation. See [Authentication](/mcp/authentication).

<Tabs>
  <Tab title="Claude Code">
    1. Add the server to `~/.claude.json`:

       ```json
       {
         "mcpServers": {
           "neetoauth": {
             "type": "http",
             "url": "https://connect.neetoauth.com/mcp/messages",
             "headers": {
               "Authorization": "Bearer YOUR_API_KEY"
             }
           }
         }
       }
       ```

    2. Restart Claude Code.
  </Tab>

  <Tab title="Cursor">
    1. Add the server to `~/.cursor/mcp.json`:

       ```json
       {
         "mcpServers": {
           "neetoauth": {
             "type": "http",
             "url": "https://connect.neetoauth.com/mcp/messages",
             "headers": {
               "Authorization": "Bearer YOUR_API_KEY"
             }
           }
         }
       }
       ```

    2. Restart Cursor.
  </Tab>

  <Tab title="Gemini CLI">
    1. Add the server to `~/.gemini/settings.json`. Use `httpUrl`, not `url`:

       ```json
       {
         "mcpServers": {
           "neetoauth": {
             "httpUrl": "https://connect.neetoauth.com/mcp/messages",
             "headers": {
               "Authorization": "Bearer YOUR_API_KEY"
             }
           }
         }
       }
       ```

    2. Restart Gemini CLI.
  </Tab>

  <Tab title="Codex">
    1. Add the server to `~/.codex/config.toml`:

       ```toml
       [mcp_servers.neetoauth]
       url = "https://connect.neetoauth.com/mcp/messages"
       bearer_token_env_var = "NEETOAUTH_API_KEY"
       ```

    2. Set `NEETOAUTH_API_KEY` to your API key in the shell where you run Codex.
  </Tab>

  <Tab title="VS Code">
    You need VS Code 1.99 or later, with GitHub Copilot in **Agent** mode.

    1. Create `.vscode/mcp.json` in your workspace:

       ```json
       {
         "inputs": [
           {
             "type": "promptString",
             "id": "neetoauth-api-key",
             "description": "NeetoAuth API key",
             "password": true
           }
         ],
         "servers": {
           "neetoauth": {
             "type": "http",
             "url": "https://connect.neetoauth.com/mcp/messages",
             "headers": {
               "Authorization": "Bearer ${input:neetoauth-api-key}"
             }
           }
         }
       }
       ```

    2. Paste your API key when VS Code asks.

    <Warning>
      This file lives in your project. Do not paste the key into the file itself, or it can end up in a commit.
    </Warning>
  </Tab>

  <Tab title="Windsurf">
    1. Add the server to `~/.codeium/windsurf/mcp_config.json`. Use `serverUrl`, not `url`:

       ```json
       {
         "mcpServers": {
           "neetoauth": {
             "serverUrl": "https://connect.neetoauth.com/mcp/messages",
             "headers": {
               "Authorization": "Bearer YOUR_API_KEY"
             }
           }
         }
       }
       ```

    2. Turn on the server under **Settings → Cascade → MCP Servers**.
  </Tab>

  <Tab title="Antigravity">
    1. Open **Settings → Customizations → Open MCP Config**.
    2. Add the server to `mcp_config.json`. Use `serverUrl`, not `url`:

       ```json
       {
         "mcpServers": {
           "neetoauth": {
             "serverUrl": "https://connect.neetoauth.com/mcp/messages",
             "headers": {
               "Authorization": "Bearer YOUR_API_KEY"
             }
           }
         }
       }
       ```

    3. Reload Antigravity.
  </Tab>
</Tabs>

Replace `YOUR_API_KEY` with a key from your workspace. [Learn how to generate your API key.](https://help.neetoauth.com/articles/api-keys)

## Confirm the connection

Ask the assistant *"Which neeto products are enabled in my NeetoAuth workspace?"* If it answers with your products, the connection works. For more prompts, see [Examples](/mcp/examples). If it does not work, see [Troubleshooting](/mcp/troubleshooting).
