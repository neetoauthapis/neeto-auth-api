Use the CLI with an AI coding assistant to manage NeetoAuth in plain language. The `neetoauth setup` commands add NeetoAuth instructions for your assistant, while [`--toon`](/cli/output-formats) keeps command output compact for it to read.

## Set up your assistant

Run the subcommand for the tool you use:

| Command | What it does |
| --- | --- |
| `neetoauth setup claude` | Extracts the NeetoAuth plugin (manifest, marketplace, session-start hook, and skill) to `~/.config/neetoauth/claude-plugin`, replacing any earlier copy. Requires `~/.claude/` to exist. |
| `neetoauth setup cursor` | Writes `.cursor/rules/neetoauth.mdc`. Overwrites the file. |
| `neetoauth setup windsurf` | Writes `.windsurf/rules/neetoauth.md`. Overwrites the file. |
| `neetoauth setup copilot` | Adds a NeetoAuth section to `.github/copilot-instructions.md`. Keeps the rest of the file. |
| `neetoauth setup gemini` | Adds a NeetoAuth section to `GEMINI.md`. Keeps the rest of the file. |
| `neetoauth setup codex` | Adds a NeetoAuth section to `AGENTS.md`. Keeps the rest of the file. |

Every subcommand except `setup claude` writes into the current directory, so run it from the root of the project the assistant works in. The `copilot`, `gemini`, and `codex` commands place their section between `<!-- neetoauth:start -->` and `<!-- neetoauth:end -->` markers and replace that section on re-run instead of adding a duplicate. Re-run the command after every CLI upgrade so the instructions match the installed version.

```bash
neetoauth setup claude
```

`setup claude` prints two slash commands to finish the installation inside Claude Code:

```text
/plugin marketplace add ~/.config/neetoauth/claude-plugin
/plugin install neetoauth@neetoauth
```

After setup, your assistant can check the commands and flags available in your installed CLI version:

```bash
neetoauth commands
```

The command prints the complete catalog as JSON.

## Tips for agent workflows

<Tip>
  Prefer `--toon` when the assistant needs to read a list or record, and
  `--quiet` when it needs to pipe an identifier into the next command. See
  [Output formats](/cli/output-formats).
</Tip>

- Authenticate once with [`neetoauth login`](/cli/authentication); the assistant reuses the stored credentials.
- When several workspaces are signed in, the assistant must pass `--subdomain <name>` on each command.
- Run [`neetoauth doctor`](/cli/troubleshooting) first to confirm the assistant is authenticated and connected.
- Have the assistant run `neetoauth products list` before inviting anyone, so it uses product and role names that exist in the workspace.

<Note>
  The CLI acts as the person who signed in, so an assistant can only do what
  you can do. To give an assistant workspace-wide access instead, connect the
  [MCP server](/mcp/introduction) with an API key.
</Note>
