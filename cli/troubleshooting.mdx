## Run the doctor

When something goes wrong, start with `neetoauth doctor`. It checks your authentication, API connection, and CLI version.

```bash
neetoauth doctor
```

When multiple workspaces are signed in, name the one to check:

```bash
neetoauth doctor --subdomain your-workspace
```

## Common errors

When a command fails, it prints an error message to standard error and exits with status 1. For a usage mistake, such as an unknown flag or a missing argument, it adds `Run 'neetoauth --help' for usage.`

<AccordionGroup>
  <Accordion title="not authenticated. Run 'neetoauth login' to authenticate">
    **Problem**: no workspace is signed in. <br />
    **Solution**: run [`neetoauth login --subdomain <name>`](/cli/authentication).
  </Accordion>
  <Accordion title="multiple subdomains authenticated (acme, globex); specify --subdomain">
    **Problem**: more than one workspace is signed in, so the target is ambiguous. <br />
    **Solution**: add `--subdomain <name>` to the command. For `logout`, `--all` is also accepted.
  </Accordion>
  <Accordion title='not authenticated for "foo". Authenticated subdomains: acme, globex'>
    **Problem**: the `--subdomain` value does not match any signed-in workspace. <br />
    **Solution**: use one of the listed subdomains, or [sign in](/cli/authentication) to the new one.
  </Accordion>
  <Accordion title="subdomain not found, please check that you entered the correct subdomain">
    **Problem**: `login` could not find a workspace at that subdomain. <br />
    **Solution**: use only the first part of your workspace URL. For `https://acme.neetoauth.com`, enter `acme`.
  </Accordion>
  <Accordion title="neetoauth cli authentication timed out after 2 minutes, please try again">
    **Problem**: `login` waited two minutes without the browser sign-in finishing. The related message `authentication session expired, please try again` means the server ended the sign-in session first. <br />
    **Solution**: run `neetoauth login` again and finish the browser step promptly. If the browser did not open, visit the URL the CLI printed.
  </Accordion>
  <Accordion title="could not connect to NeetoAuth. Check your internet connection">
    **Problem**: the CLI could not reach your workspace. <br />
    **Solution**: check your network and any proxy, then run `neetoauth doctor` to confirm the API is reachable.
  </Accordion>
  <Accordion title="--email is required">
    **Problem**: `users create` ran without an email address. <br />
    **Solution**: pass `--email <address>`, or supply it in the file given to `--json-file`.
  </Accordion>
  <Accordion title="--role is required (e.g. owner, non_owner)">
    **Problem**: `users create` ran without an organization role. <br />
    **Solution**: pass `--role owner` or `--role non_owner`. This is the organization-level role, not a product role.
  </Accordion>
  <Accordion title='invalid --app value "Cal" (expected name:role)'>
    **Problem**: an `--app` value is missing the role half. <br />
    **Solution**: write it as `name:role`, for example `--app Cal:Admin`. Run `neetoauth products list` to see the valid pairs.
  </Accordion>
  <Accordion title='product "Foo" not found. Run "neetoauth products list" to see available products'>
    **Problem**: `products enable` or `products disable` was given a name that is not a product in the workspace. <br />
    **Solution**: use the `name` shown by `neetoauth products list`. Names are matched without regard to case.
  </Accordion>
  <Accordion title="claude Code not found (~/.claude/ does not exist)">
    **Problem**: `setup claude` ran on a machine where Claude Code has never been started. <br />
    **Solution**: install and open Claude Code once, then run `neetoauth setup claude` again.
  </Accordion>
  <Accordion title="API error (422): Unknown product: Foo">
    **Problem**: the server rejected the request. The CLI prints `API error (<status>): <message>`, taking the message from the `error`, `notice`, or `errors` field of the response, and adds a `Suggestion:` line for common statuses: 401 (sign in again), 403 (no permission), 404 (resource not found), 422 (check the required fields), and 429 (rate limited). Typical causes are inviting someone who is already an active member, an `--app` product or role the workspace does not offer, or removing the last owner. <br />
    **Solution**: read the message and the suggestion, fix the input, and retry. For a 401, run `neetoauth login` again.
  </Accordion>
</AccordionGroup>

## Permission errors

The CLI acts as the person who signed in, so commands are checked against your own permissions. A command you are not allowed to run fails with `API error (403)` and the suggestion `You do not have permission to perform this action.` Ask a workspace owner to grant you the permission, or use an [API key](/api/authentication) against the REST API instead. Enabling or disabling products needs permission to manage workspace settings.

## Check the version

```bash
neetoauth version
```

Prints the CLI version, commit hash, and build date - useful when reporting an issue. Run `neetoauth update` to move to the latest release.
