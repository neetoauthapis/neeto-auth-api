These commands manage the CLI itself rather than a NeetoAuth resource.

## Authentication

### login

```bash
neetoauth login --subdomain your-workspace
```

Opens your browser to sign in and saves credentials for the workspace. Omit `--subdomain` to be prompted. If the browser does not open, the CLI prints the sign-in URL for you to visit, and it waits up to two minutes for you to finish.

```text Sample output
Opening browser for authentication...
If the browser doesn't open, visit: https://acme.neetoauth.com/api/cli/v1/login?token=...
Waiting for authentication... done!
Authenticated as oliver@example.com on acme.neetoauth.com.
```

### logout

```bash
neetoauth logout --subdomain your-workspace
neetoauth logout --all
```

<LogoutFlags />

```text Sample output
Signed out of acme.neetoauth.com.
```

With `--all`, it prints `Signed out of all subdomains.` instead. With neither flag, it signs out of the only saved workspace, or fails with `Multiple subdomains authenticated (acme, globex); specify --subdomain or --all.` when several are saved. When nothing is saved it prints `Not authenticated.`.

### whoami

```bash
neetoauth whoami
```

Lists each signed-in account and marks it `(default)` when only one is signed in. Pass `--subdomain <name>` to show one workspace.

```text Sample output
Authenticated as oliver@example.com on acme.neetoauth.com (default).
```

## Diagnostics

### doctor

```bash
neetoauth doctor
```

Checks authentication, API reachability, and the CLI version. See [Troubleshooting](/cli/troubleshooting). When several workspaces are signed in, pass `--subdomain <name>`.

```text Sample output
✓ Authentication: authenticated as oliver@example.com on acme.neetoauth.com
✓ API connection: https://acme.neetoauth.com (responding in 214ms)
✓ CLI version: 1.0.10
```

A failed check is marked `✗`. An authentication failure carries the reason on the same line, and a connection failure carries the underlying error on the next line. When no workspace is signed in and `--subdomain` is not given, the API connection check is skipped.

### version

```bash
neetoauth version
```

Prints the CLI version, commit hash, and build date.

```text Sample output
neetoauth 1.0.10 (commit: a1b2c3d, built: 2026-08-04)
```

With `--json`, or when output is piped, it prints the same fields as an object:

```json Sample output (--json)
{
  "binary": "neetoauth",
  "version": "1.0.10",
  "commit": "a1b2c3d",
  "date": "2026-08-04"
}
```

### commands

```bash
neetoauth commands
```

Prints the complete command and flag catalog for the installed version as JSON. It is useful in scripts and with AI assistants. The catalog leaves out `help`, `completion`, and `commands` itself, and the [global flags](/cli-reference/overview#global-flags) are not repeated under each command.

```json Sample output
[
  {
    "command": "neetoauth users",
    "description": "Manage workspace team members",
    "subcommands": [
      {
        "command": "neetoauth users list",
        "description": "List active team members in the workspace",
        "flags": [
          { "name": "page", "type": "int", "default": "0", "description": "Page number" }
        ]
      }
    ]
  }
]
```

## Updating

### update

```bash
neetoauth update
```

Detects how the CLI was installed and runs the matching upgrade for you. It always installs the latest release; there is no way to pick an older version.

```text Sample output
Detected Homebrew install.
Running: brew update && brew upgrade neetozone/homebrew-tap/neetoauth
```

Outside Homebrew it reports a `shell-script` install on macOS and Linux, or a `Windows` install on Windows, and runs the matching installer. If the installer fails, the command fails too.

## AI-assistant setup

Add NeetoAuth instructions to your AI coding assistant. See [AI assistants](/cli/ai-assistants) for what each target writes.

```bash
neetoauth setup claude
neetoauth setup cursor
neetoauth setup windsurf
neetoauth setup copilot
neetoauth setup gemini
neetoauth setup codex
```

```text Sample output
NeetoAuth plugin extracted to /Users/oliver/.config/neetoauth/claude-plugin

To finish installation, open Claude Code and run these slash commands:
  /plugin marketplace add /Users/oliver/.config/neetoauth/claude-plugin
  /plugin install neetoauth@neetoauth
```

The other assistants write a rules or instructions file into the current project directory, reporting `Wrote <path>` or `Updated <path>`.

## Shell completion

Shell completion fills in command names, subcommands, and flags when you press `Tab`. It saves you from having to remember the full command tree or look up `--help`.

`neetoauth completion <shell>` installs completion for your shell. For zsh, bash, and PowerShell it writes a script under `~/.config/neetoauth/completions` and adds a marked block to `~/.zshrc`, `~/.bashrc`, or `~/Documents/PowerShell/Microsoft.PowerShell_profile.ps1` that loads the script the next time the shell starts. For fish it writes `~/.config/fish/completions/neetoauth.fish`, which fish loads on its own.

<CodeGroup>
```bash Zsh
neetoauth completion zsh
```

```bash Bash
neetoauth completion bash
```

```bash Fish
neetoauth completion fish
```

```powershell PowerShell
neetoauth completion powershell
```
</CodeGroup>

Start a new shell (or run `source ~/.zshrc`) to enable it. After upgrading the CLI, run the command again to update the available completions. Re-running it replaces the existing script and configuration without adding duplicates.

<Note>
  To configure it yourself, pass `--print` to write the raw script to standard output instead of installing it:

  ```bash
  neetoauth completion zsh --print
  ```
</Note>
